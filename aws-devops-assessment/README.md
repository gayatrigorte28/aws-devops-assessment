**Candidate:** Gayatri Gorte

This repository is a starter implementation for an AWS web application platform. It includes Terraform infrastructure, a small demo application, a GitHub Actions workflow, an architecture diagram, and validation instructions.

## Important cost and deployment note
This repository is prepared for review and local validation first. **Do not run `terraform apply` unless you have approval, understand the AWS charges, and have checked the AWS Pricing Calculator.** NAT Gateway, Application Load Balancer, RDS, EC2, S3 requests, Secrets Manager, and logging can incur charges.

To keep accidental costs lower, expensive infrastructure switches default to `false`. The Terraform code includes the corresponding resources and can be enabled deliberately after review. A real HTTPS URL, AWS screenshots, and live health-check evidence can only be produced after an actual deployment and verification. Do not claim a deployment happened if it did not.

## Local validation
Install Terraform and Git. From the repository root:
```powershell
cd terraform
terraform fmt -recursive
terraform init -backend=false
terraform validate
```
These commands initialize providers and validate configuration; they do not create AWS infrastructure. `terraform init` may need internet access to download the AWS provider.

## GitHub Actions
The workflow runs formatting and validation on pull requests and pushes. It does **not** deploy resources. The workflow uses `terraform init -backend=false` and `terraform validate`.

## Optional infrastructure
In `terraform/terraform.tfvars.example`, switches for cost-bearing components are set to `false`. Review the full configuration and set values intentionally only when authorized:
- `enable_nat_gateway`
- `enable_compute`
- `enable_database`
- `enable_alb`
- `enable_https`

HTTPS requires a valid ACM certificate ARN in the same AWS region as the ALB. For a public certificate, validate domain ownership in ACM first.

## Security notes
- Never commit AWS access keys, private keys, passwords, `.tfstate`, or `.tfvars` containing secrets.
- Use GitHub OIDC and an AWS IAM role rather than long-lived AWS keys if you later add deployment.
- Database credentials are generated by Secrets Manager when the database is enabled.
- Restrict ingress CIDRs and IAM permissions before any real deployment.
- The demo app is static HTML and does not connect to the database.
